# HW-S0 — DHT11 stop-gap firmware (CHAT-52), 23 Nov 2026

**Scope.** Firmware env `esp32dev_dht11`: reads a DHT11 module (DATA on GPIO 4, VCC 3V3, GND) and sends `sensor_model` "DHT11". Wi-Fi, TLS, buffer, acknowledgements and contract L3B v1 are unchanged. The SHT30 env `esp32dev` stays the default and unchanged.

**Contract.** Failures are never values: bad checksum, all-zero frame and RH above 100 % are `CRC_ERROR`; no answer to the start signal is `NO_ACK`; a missing edge is `TIMEOUT`. One retry after the 1.1 s minimum interval.

**Excluded.** Accuracy of the DHT11, storage thresholds for DHT11 readings, the real board. DHT11 readings show the data flow only; paper measurements need the SHT30 (O75).

**Files.** `firmware/lib/kn_core/src/dht11_codec.h` (new), `firmware/include/config.h`, `firmware/platformio.ini`, `firmware/src/main.cpp`, `firmware/test/test_native/test_main.cpp`.

**Tests (run 23 Nov 2026).**
- `pio test -e native`: 16/16 pass (3 new DHT11 cases: decode, negative temperature, failures not values).
- `pio run` for `esp32dev`, `esp32dev_dht11`, `wokwi`: all SUCCESS (DHT11 build: flash 70.3 %, RAM 19.5 %).
- `esp32dev_dht11` also builds with a `secrets.h` generated by `scripts/provision_node.py` (HW-S2).

**Not verified.** The real board; bit timing with Wi-Fi active. Firmware builds are not in CI yet.
